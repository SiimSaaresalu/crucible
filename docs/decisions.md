# Decisions

One line for each design decision, with the date and the reason.

- 2026-11-14 — Agent interface: MCP, not the CLI fallback. In Harbor 0.26.0, OpenCode with `google/gemini-3.8-flash` saw and called the typed MCP tools (valid enum arguments). The MCP server ran in its own container. The verifier got the grade from a token-protected `/grade` route, and a request without the token got 403. Evidence: `spikes/hello-mcp-ns/README.md`.
- 2026-11-14 — Gemini key name: `GOOGLE_GENERATIVE_AI_API_KEY`. OpenCode reads this name. Pass it with `--api-key-name GOOGLE_GENERATIVE_AI_API_KEY --ae GOOGLE_GENERATIVE_AI_API_KEY=$GOOGLE_GENERATIVE_AI_API_KEY`; without these flags the run fails with `ProviderAuthError`.
- 2026-11-14 — Pin Harbor to 0.26.0. OpenCode is still unpinned (`opencode-ai@latest`); pin it before the submission runs and write both versions in the README.
- 2026-11-14 — Grading path: in build step 6 or 7, try Harbor's separate verifier with a `[[verifier.collect]]` hook (the `sidecar-artifacts` example): the hook runs in the sidecar after the agent stops and writes the grade to a file; the grade route listens only on localhost. Check it with a short spike first, because `[[verifier.collect]]` is not in the config reference. Fallback: the token-protected `/grade` route from `spikes/hello-mcp-ns` (token only in `[verifier.env]`, never in `[environment.env]`).
- 2026-11-14 — Engine tooling: Python 3.14 everywhere (`engine/.python-version`, `mise.toml`, `requires-python = ">=3.14"`, ruff `py314`, pyright 3.14); no older-Python floor, because the code only runs where we control the interpreter. pyright runs in strict mode. The `engine` CI workflow runs only for changes to `engine/**`, `configs/**` and its own file, so doc-only PRs skip it.
- 2026-11-14 — `Observation` shape: `text`, `data`, `last_result`. The brief uses `Observation` but never defines it; this is the smallest shape that lets a policy see the last tool result without any hidden task state.
- 2026-11-14 — `Task.instruction()` added to the brief's `Task` interface. `Policy.reset` needs the instruction text, and the task is the only source of it.
- 2026-11-14 — Policy registry keyed by `(name, task_id)`, with a fallback to task-agnostic policies (`task_id=None`, e.g. `do_nothing`). Jobs are data (`Job(policy="reference")`), and reference policies belong to one task each.
- 2026-11-14 — RNG sub-seeds come from `sha256(f"{seed}:{name}")`, not `hash()`. `hash()` of a string is salted per process, so it would give a different world on every run.
- 2026-11-14 — Transcript: one JSONL file per episode (header, steps, footer; `schema_version` 1), written to `<path>.tmp` and renamed on close; resume means the file exists. A file that exists is therefore complete, so the executor can skip it safely. Only `InfraError` is retried; a resumed job reports `retried=0` because the retry count is not in the file.
- 2026-11-14 — `incident` reward is normalised by the oracle gain (the do-nothing loss minus the oracle loss), not by `lost_if_nothing_done`. A perfect early repair still loses some service during repair time, so dividing by the do-nothing loss would cap the best possible score below 1.
- 2026-11-14 — `recovered` is counted over the whole horizon, not only over the fault window as in the brief. A restart or rollback in the healthy phase loses real requests, and counting only the fault window would hide that loss.
- 2026-11-14 — Repair classification: damage in the healthy phase and a wrong repair are two separate penalties, and each action is counted once. Otherwise one bad action could be charged twice.
- 2026-11-14 — The incident simulation is pure functions over `(world, interventions, minute)`. Do-nothing and oracle are replays with `[]` and `[correct repair at fault_start]`, so both use the same code as the agent run and do-nothing is exactly 0 and the oracle exactly 1, with no rounding in the simulation.
- 2026-11-14 — `incident@1` step budget is 40, `wait` takes at most 30 minutes, and alert names never equal a root-cause string. The budget and wait cap bound the episode length; the alert rule stops the alert text from giving the answer.
- 2026-11-14 — Scripted test solvers (informed, shotgun, stop_early, scale_only) may read the hidden world; real policies may not. The scripts exist to calibrate scoring and check the grader, and they need to know the truth to act as upper and lower bounds.
- 2026-11-14 — Calibration finding: for a correct repair, the reward is roughly the share of the fault window before the repair starts, because fault effect factors and repair durations cancel out in recovered / oracle_gain. The reference score is therefore driven by detection time (alert holds) and the number of reads before the repair. Scripted solvers over seeds 0–29: informed mean 0.949 (min 0.902, max 0.974), shotgun mean 0.011, stop_early 0.000, scale_only 0.000.
- 2026-11-14 — Incident policies parse tool results through `policies/incident_views.py` and never import the task's world, sim, state or grader; an `ast` test enforces it. The reference must be drivable later over MCP with the same class.
- 2026-11-14 — `stop_early` picks its cause from a sha256 of the two results it read, not from `random`, because `Policy.reset` gets no seed and episodes must be deterministic.
- 2026-11-14 — The reference is a runbook: wait for an alert, read logs upstream along the topology, repair only after a log signature, confirm, resolve. Alerts without a signature are treated as noise; herring names are not hard-coded.
- 2026-11-14 — "Reference as a script against the server" moves to step 6, because the server does not exist yet; the reference is a plain `Policy` so `solve.sh` can drive it through an MCP client.
- 2026-11-14 — `nightshift eval` runs all policies in one executor call, so one `summary.csv` covers the whole comparison and `--out` reuse resumes it.
- 2026-11-14 — Golden scores per (task ref, policy, seed) live in `engine/tests/policies/golden_scores.json`; a score change without a version bump fails CI. Regenerate with `NIGHTSHIFT_UPDATE_GOLDEN=1` only when the change is intended for the current version.
- 2026-11-14 — Measured means on seeds 0–99 (`nightshift eval --task incident@1 ... --seeds 0-99`): reference 0.968 (min 0.931, max 0.983), stop_early 0.000, shotgun 0.012, do_nothing 0.000.
- 2026-11-14 — The reference's per-seed ceiling is `< 0.99` (the oracle scores exactly 1), not the scripted `Informed` mean, because `Informed` reads three times before repairing and is not an upper bound.
- 2026-11-14 — One app, two modes (`MODE=api` serves `/healthz` and `/v1`; `MODE=sidecar` serves `/healthz`, `/mcp` and `/grade`). In the Harbor sidecar the agent can reach every route, so `/v1` is off there (the agent could start its own episodes on the same seed and read scores), and api mode has no `/grade` or `/mcp`.
- 2026-11-14 — MCP uses the official SDK's low-level `Server` (mcp 2.x, `on_list_tools` / `on_call_tool` handlers) with a stateless, JSON-response `StreamableHTTPSessionManager` mounted at `/mcp`, because the tools come from `ToolSpec` at runtime and the low-level API takes the JSON Schema directly.
- 2026-11-14 — `GET /grade` (header `x-grade-token`, `hmac.compare_digest`, 403 otherwise) closes the episode, returns the reward, breakdown, flags, steps, stop reason and the transcript, and is idempotent; later MCP calls get "Episode is closed". `GRADE_TOKEN` is required at startup in sidecar mode.
- 2026-11-14 — Harbor export vendors the engine as a wheel (`uv build` + `uv export --no-dev`) into each task's `environment/mcp-server/` and `solution/`, not a local image tag. Each task builds on its own (laptop or a cloud sandbox with no registry), and the ten identical build contexts share the Docker cache.
- 2026-11-14 — No engine in the agent's container (`main` is `ubuntu:24.04` + curl + python3, as in the spike). With the simulator and internet an agent could replay seeds and match observations. The oracle's `solve.sh` installs uv 0.12.18 and Python 3.14 at run time; Harbor uploads `solution/` only for the oracle.
- 2026-11-14 — One new `secrets.token_hex(16)` grade token per task per export, only in `[verifier.env]` and the sidecar's compose environment. Generated folders are build output (`harbor/` is gitignored), because a token in a public repo is readable by an agent with internet.
- 2026-11-14 — The verifier writes the breakdown to `grade.json`, not `reward.json`. Harbor 0.26.0 reads `reward.json` as a dict of numeric rewards and fails with `VerifierOutputParseError` on our nested breakdown; `reward.txt` holds the single 0–1 reward.
- 2026-11-14 — Harbor oracle rewards equal the in-process reference scores on seeds 0–9 (mean 0.971), and `nop` scores 0. The sidecar path is as deterministic as the in-process loop. Runs: `docs/harbor-runs.md`.
- 2026-11-14 — Pin OpenCode to 1.19.5 (`--ak version=1.19.5`) and run it with `--ak disable_web_search=true`.
- 2026-11-14 — No `[agent].allowed_hosts` in the generated tasks. In Harbor 0.26.0, `network_mode = "allowlist"` fails at startup on the sidecar (`conflicting options: port exposing and the container type network mode`). Without it, the agent's shell has internet access. The protections are no engine in `main`, `disable_web_search=true` and a new token on every export. Try the allowlist again on a newer Harbor version.
- 2026-11-14 — `[verifier].collect` spike not done in step 7. The token route works end to end, and the allowlist result above shows that Harbor's network options need more testing first.
- 2026-11-14 — Renamed the package and CLI `nightshift` → `crucible` (import path, `crucible` command, wheel `crucible-*.whl`, Harbor task names `crucible/<task>-seed-<n>`, env vars `CRUCIBLE_GIT_COMMIT`, `CRUCIBLE_UPDATE_GOLDEN`, `CRUCIBLE_POLICY`). Older entries keep the old names as they were written. The `incident` task title ("Night Shift: on-call incident") stays: it names the scenario, not the package.
- 2026-11-14 — One package per environment: `crucible/envs/<name>/` holds the task modules, its own `policies/`, `tests/` and a `README.md` environment card. Generic code stays in `core/`, `server/`, `agents/`, `export/`, and `policies/` keeps only `do_nothing`. Environments stay inside the `crucible` distribution (not separate packages) because the Harbor export vendors one wheel into the sidecar.
- 2026-11-14 — Environment tests live in `envs/<name>/tests/` (pytest `testpaths` includes `src/crucible/envs`) and are left out of the wheel (`[tool.uv.build-backend] wheel-exclude`), so the calibration scripts that read the hidden world never ship to the sidecar or `solution/`. Shared test helpers moved from `tests/core/helpers.py` to the public `crucible.testing` (`ScriptedPolicy`, `play`) so env tests, including plugin ones, do not import the top-level `tests` package.
- 2026-11-14 — Environments are discovered through the `crucible.envs` entry point group; the built-ins are declared there too (`guess`, `incident`), so built-ins and plugins load the same way. Entry points load sorted by name for a stable registration order; an import failure raises `EnvLoadError` naming the entry point, and the next lookup retries. Golden scores and the hidden-import `ast` test stay central in `engine/tests/policies/` and cover every environment.
- 2026-11-14 — Re-check after the rename and move: golden scores regenerated with no diff; `crucible eval --seeds 0-99` gives the same means as before (reference 0.968, stop_early 0.000, shotgun 0.012, do_nothing 0.000); Harbor oracle on seeds 0–9 equals the golden reference score on every seed (mean 0.971, 10/10 root cause correct); one OpenCode 1.19.5 + `google/gemini-3.8-flash` trial on seed 0 scored 0.918 in 12 steps with the right root cause, using MCP tools only — the same reward as the step-7 run on seed 0. Runs: `docs/harbor-runs.md`.
- 2026-11-14 — PRs 10 and 11 (`--task` required for `play` and `export harbor`; salt, generic task checks, task resources, `new-env`) were merged into their stacked base branches, not into `main`. Ported onto `main` after the rename. Discovery keeps the entry points: `new-env` writes `envs/<name>/` (task, `policies/reference.py`, `tests/`, `README.md`) and adds `<name> = "crucible.envs.<name>"` to the `crucible.envs` table in `pyproject.toml`; the next `uv run` reinstalls the project, so the registry finds it. `test_scaffold.py` runs the copy from `PYTHONPATH` with a stand-in `.dist-info` built from the copy's `pyproject.toml`, because the copy is not installed.
